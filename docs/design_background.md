# 小牛U1 FOC模拟器 - 开发笔记

## 项目背景

用户的2021款小牛U1电动车FOC电机控制器损坏，需要制作一个模拟设备替代原车FOC控制器发送485报文，让电动车其他控制器(中控、仪表、电池)认为FOC正常工作。

## 需求分析

### 原始问题
- FOC电机控制器损坏
- 需要替代品模拟FOC发送正常通信
- 让中控能够解锁挡位，实现正常骑行

### 最终功能设计
1. **核心**: 模拟FOC控制器485通信协议 (响应 V35 ECU 轮询)
2. **测速**: 霍尔传感器测量轮速, OLED 实时显示
3. **能耗**: 精确计算电池能耗

> 原计划的「BLE 防丢器接近自动解锁」已于 2026-10-20 放弃, 详见"已放弃的方案".

### 帧格式 (小牛U1)
```
Byte[0]   0x68       # 帧头
Byte[1]   地址       # 设备地址
Byte[2]   地址反码   # 地址取反
Byte[3]   0x68       # 帧头
Byte[4]   功能码     # 0x02查询, 0x82响应, 0x01控制
Byte[5]   字节数     # 数据长度
Byte[6..] 数据      # 每个字节需减0x33才是真实值
Byte[-2]  校验和     # 从帧头到数据最后一字节累加
Byte[-1]  0x16       # 帧尾
```

### 设备地址
| 设备 | 地址 |
|------|------|
| FOC控制器 | 0x20 |
| 电池BMS | 0x31 |
| 仪表Dash | 0x10 |

### 关键命令解析

#### 1. 中控查询FOC状态
```
发送: 68 20 DF 68 02 02 05 08 XX XX 16
      ──┬── ──┬── ──┬
      地址  地址反码 功能

回复: 68 20 DF 68 82 0E [数据14字节] XX 16
      数据格式(解密后):
      [0] 0x30 保留
      [1] 0x26 保留
      [2] 0x3C 保留
      [3] 速度低字节
      [4] 速度高字节
      [5] 0x01 保留
      [6] 0x00 保留
      [7] 0x16 保留
      [8] 0x00 保留
      [9] 0x00 保留
      [10] 挡位(1-3)
      [11] 0x00 保留
      [12] 错误码
      [13] 0x00 保留
```

#### 2. 中控发送解锁命令
```
发送: 68 20 DF 68 01 01 03 XX XX 16

回复: 68 20 DF 68 81 10 [16字节数据] XX 16
      固定回复: 4D 55 31 33 33 37 33 42 33 33 32 30 30 32 31 36
```

#### 3. 速度映射(协议值0-31转实际km/h)
```
参考抓包数据:
| 协议值 | 实际km/h |
|--------|----------|
| 0      | 0        |
| 3      | 1        |
| 5      | 2        |
| 7      | 3        |
| 10     | 4        |
| 13     | 6        |
| 17     | 8        |
| 21     | 10       |
| 25     | 12       |
| 30     | 14       |
| 31     | 15+      |
```
反向换算 (代码里 `calcFOCSpeedFromKMH`): 0→0, 1→3, 2→5, 3→7, 4→10, 5/6→13,
7/8→17, 9/10→21, 11/12→25, 13/14→30, 15+→31.

> 表只覆盖到 15 km/h, 超过就发 31 (封顶). 调试时写死的 17 km/h 对应的就是协议值 31.

## 硬件设计

### 最终选型
| 配件 | 型号 | 原因 |
|------|------|------|
| 主控 | ESP32-C3 DevKit | 性价比高，支持BLE，内置WiFi |
| 485芯片 | MAX485 | 经典方案，资料多 |
| 轮速 | 霍尔传感器A3144 | 便宜可靠，无需维护 |
| 电源 | XL7015降压模块 | 48-60V输入，输出5V |

### 接线表
```
信号部分:
GPIO7  (TX)  → MAX485 DI
GPIO4  (RX)  → MAX485 RO
GPIO3        → 霍尔传感器 OUT (外部中断)

MAX485: DE/RE 短接后接地（自动方向，半双工）

电源部分:
电池+(48V) → XL7015 VIN+
电池-(GND) → XL7015 VIN-

XL7015 VOUT+ → ESP32 5V
XL7015 VOUT+ → MAX485 VCC
XL7015 VOUT+ → 霍尔传感器 VCC

XL7015 VOUT- → ESP32 GND
XL7015 VOUT- → MAX485 GND
XL7015 VOUT- → 霍尔传感器 GND
```

### 串口参数
```
485 串口: Serial1 (UART1)
波特率: 9600
数据格式: 8E1 (8位数据，偶校验，1位停止位)
引脚: GPIO7=TX, GPIO4=RX
校验和: sum & 0xFF (字节 0 到 CS 之前累加, 取低 8 位)

USB 调试串口: Serial (UART0, USB CDC)
波特率: 115200
数据格式: 8N1
引脚: 板载 CH340K (GPIO20/21)
```

> ⚠️ ESP32-C3 引脚限制（务必先看这里再选引脚）：

| GPIO | 状态 | 用途 / 限制 |
|------|------|-------------|
| GPIO0 | ⚠️ 限制 | Strapping Pin (启动时必须为低, 决定 boot 模式). 上拉后能用作普通 GPIO, 但需要外部电路. |
| GPIO1 | ⚠️ 限制 | Strapping Pin (启动时必须为高, 决定 ROM 日志打印). 一般不用. |
| **GPIO2** | ⚠️ 限制 | Strapping Pin (启动时必须悬空/低, 决定 flash 启动电压). **上电瞬间若被外部拉高, 可能进不去正常 boot 模式**. 若用作普通 GPIO, 必须确认外接电路不会改变上电时的电平. |
| GPIO3 | ✅ 安全 | 通用 GPIO. 无特殊限制. |
| GPIO4 | ✅ 安全 | 通用 GPIO. 无特殊限制. |
| GPIO5 | ✅ 安全 | 通用 GPIO. 无特殊限制. |
| GPIO6 | ✅ 安全 | 通用 GPIO. 无特殊限制. |
| GPIO7 | ✅ 安全 | 通用 GPIO. 无特殊限制. |
| GPIO8 | ⚠️ 限制 | Strapping Pin (启动时电平决定下载模式). 一般不用, 用作 GPIO 会影响 BOOT 检测. |
| GPIO9 | ⚠️ 限制 | Strapping Pin + 板载 BOOT 键 (天问 TW002). 硬件上已经有按键, 用作 GPIO 会跟 BOOT 冲突. |
| GPIO10 | ✅ 安全 | 通用 GPIO. 无特殊限制. |
| GPIO11-17 | 🚫 禁用 | 内部 SPI Flash 占用, 完全不能分配给用户. |
| GPIO18/19 | 🚫 禁用 | USB D-/D+, 板载 USB 串口必须占用. |
| GPIO20/21 | 🚫 禁用 | UART0 RX/TX, 默认给 USB CDC 串口用 (即使不用 USB 也别碰, boot ROM 启动日志走这里). |

**总结**: ✅ 完全安全的 GPIO 仅有 **3、4、5、6、7、10** 六个. 其它要么禁用, 要么是 strapping pin 必须确认外接电路不会干扰上电电平.

**本项目引脚分配**:
- GPIO3 → 霍尔传感器 (外部中断, 输入)
- GPIO4 → MAX485 RO (485 RX, 输入)
- GPIO5 → OLED SDA (I2C0, 板载 SSD1306)
- GPIO6 → OLED SCL (I2C0, 板载 SSD1306)
- GPIO7 → MAX485 DI (485 TX, 输出)

(所有 5 个外设引脚都是 ✅ 安全的, 没有一个落在 strapping 或 flash/USB 范围.)

## 软件架构

### 主程序流程
```
setup():
  1. Serial.begin(115200)              # USB CDC 调试日志
  2. Wire.begin(5, 6) + setClock       # OLED I2C0, 必须最早初始化
  3. Serial1.begin(9600, 8E1, 4, 7)    # 485 总线 (RX=GPIO4, TX=GPIO7)
  4. esp_log_level_set(*)              # 静音 ESP-IDF 日志
  5. simulator.begin()                 # 霍尔中断 (INPUT_PULLUP + FALLING)
  6. u8g2.begin()                      # OLED

loop():
  1. 处理 485 接收数据 (FOC 协议解析 + 应答)
  2. 每 250ms 更新轮速 (脉冲计数 → RPM → km/h)
  3. 每 200ms 刷新 OLED (只显示速度)
  4. 每 3 秒输出一次状态日志
```

### OLED 显示
只显示速度, 不显示解锁状态/BLE 信号/设备列表:
```
┌────────────────────────┐
│                        │
│        23.4  km/h      │  ← 大字车速 (十分位)
│                        │
│  124 RPM        ERR00  │  ← 轮速 + 错误码(正常时不显示)
└────────────────────────┘
```

### 轮速来源开关
```cpp
#define USE_HALL_SPEED    0      // 0=写死车速, 1=霍尔实测
#define HARDCODE_SPEED_DM 170    // 写死车速 km/h × 10 (170 = 17.0 km/h)
```
霍尔磁钢盘尚未装好, 当前用写死值把 485 通信链路和仪表显示先调通.
写死 **17.0 km/h → 协议值 31** (超出对照表范围, 31 是封顶值, 仪表显示约 17 km/h).

磁钢盘装好后把 `USE_HALL_SPEED` 改成 `1` 重新编译烧录即可 ——
写死模式下 ISR 照常挂载并在计数, 只是不用它算速度, 所以不用改其他任何代码.

### ⚠️ 霍尔传感器必须上拉
A3144 / SSR14Y 都是**开集电极**输出, 晶体管关断时输出脚浮空, 不上拉会读到随机噪声脉冲,
轮速显示全是乱跳. 代码用 `pinMode(WHEEL_SPEED_PIN, INPUT_PULLUP)` 开 ESP32 内部上拉 (~45kΩ);
线长或干扰大时建议外挂 4.7k~10k 上拉电阻. 磁铁经过时输出被拉低 → **下降沿中断 (FALLING)**.

ISR 里加了 1ms 消抖 (`now - last_pulse_us > 1000`): 6 磁钢在 30km/h 下脉冲间隔约 27ms,
所以 1ms 阈值不会漏计真实脉冲, 但能滤掉电机逆变噪声造成的毛刺.

## 已放弃的方案

### BLE 接近解锁 (2026-10-20 移除)
原设想用 BLE 防丢器的 RSSI 做无钥匙解锁 (接近自动解锁, 离开自动锁定), 已放弃并从代码中删除.

**放弃原因**:
- 红米 Watch 3 的 BLE 广播窗口极短 (1-2 秒), 高占空比扫描仍抓不稳, 且功耗高
- iPhone 不主动广播 BLE, 无法作为钥匙; 用户也没有 Mac 无法自建 iOS App
- 依赖的 WiFi AP + Web 扫描页面 (web_server.h / web_pages.h / web_config.h) 一并删除

**替代**: V35 中控的 0x01 unlock 命令直接应答成功. 挡位解锁靠中控自己判断, 不依赖外部钥匙信号.
如果以后要做无钥匙解锁, NFC (PN532, 预留 GPIO8/9) 是更可靠的方向.
