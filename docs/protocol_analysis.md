## 帧格式

### 基本格式

```
| 0 | 1    | 2      | 3 | 4    | 5      | 6...      | -2    | -1 |
| 68| 地址 | 地址反码 | 68 | 功能 | 字节数 | 帧内容...  | 校验和 | 16 |
```

### 关键规则

1. **地址反码**: `[1]地址取反 = [2]地址反码` 用于校验
2. **数据处理**: 帧内容每个字节 **减去0x33** 才是真实数据
3. **校验和**: 从帧头(0x68)到数据最后一字节的 **累加和**(取低8位)
4. **帧尾**: 固定 `0x16`

### 示例解析

#### 中控查询FOC状态
```
原始: 68 20 DF 68 02 02 05 08 XX XX 16
     ──┬── ──┬── ──┬
     地址  反码  功能

解密: 02 = 功能码(查询)
     05 08 = 子命令(查询状态)
```

#### FOC响应
```
原始: 68 20 DF 68 82 0E 63 59 6F 34 33 49 33 33 33 33 3B 33 72 16
解密后数据(减0x33):
     30 26 3C 01 00 16 00 00 00 08 00

     [0]30 = 保留
     [1]26 = 保留
     [2]3C = 保留
     [3]速度低字节
     [4]速度高字节
     [5]01 = 保留
     [6-7] = 保留
     [8]挡位
     [9-10] = 保留
     [11]错误码
```

#### FOC解锁命令
```
发送: 68 20 DF 68 01 01 03 XX XX 16
     01 = 功能码(控制)
     03 = 子命令(解锁)

回复: 68 20 DF 68 81 10 4D 55 31 33 33 37 33 42 33 33 32 30 30 32 31 36 XX 16
     81 = 控制响应(0x01 | 0x80)
     固定16字节数据
```

## FOC查询命令详解

### 状态查询 (0x02 05 08)

发送:
```
68 20 DF 68 02 02 05 08 3B 46 16
              ─── ───
              子命令
```

回复数据格式(14字节):
| 索引 | 含义 | 示例值 |
|------|------|--------|
| 0-2 | 保留 | 30 26 3C |
| 3-4 | 速度(协议值) | 00 00 (0 km/h) |
| 5 | 保留 | 01 |
| 6-7 | 保留 | 00 00 |
| 8 | 挡位(1-3) | 01 |
| 9-10 | 保留 | 00 00 |
| 11 | 错误码 | 00 |
| 12-13 | 保留 | 00 00 |

### 解锁命令 (0x01 03)

发送:
```
68 20 DF 68 01 01 03 XX XX 16
              ───
              子命令03=解锁
```

回复:
```
68 20 DF 68 81 10 [16字节固定数据] XX 16
     ─── ───
     响应 | 16字节长度
```

## 速度映射

### 协议值 → 实际速度

车速协议值是**线性刻度**, 1 格 = 12/25 = 0.48 km/h, 取值 0..127 (int8, 负数 = 倒挂)。

依据:
1. 实车跑通的 ECU 实现 `github.com/xzfn/scooter-repair` → `niu-ecu/User/niu_series_u.c`:
   ```c
   dash_request.speed = foc_speed * 12 / 25;
   g_mileage += (uint32_t)foc_speed * 12 * delta_time_ms * 10 / 36 / 25;
   ```
2. 抓包统计: FOC 车速字节最大到 44, 对应仪表字节正好是 `44 * 12 / 25 = 21` (±1)。

> 早期文档里的非线性表 (0→0, 1→3, 2→5 … 15+→31) 是把低速段的几次采样当成了
> 整张表, 实际只是 `round(kmh * 25 / 12)` 的低端取值, 且错误地把上限封在 31
> (对应 14.9 km/h)。现已按线性刻度更正。

### 计算公式

```
foc_speed = round(kmh * 25 / 12)      # 0..127
dash_kmh  = foc_speed * 12 / 25
```

举例:
| 实际车速 | 协议值 | 仪表显示 |
|---|---|---|
| 0 km/h | 0 | 0 |
| 6 km/h | 13 | 6.2 |
| 17 km/h | 35 | 16.8 |
| 21 km/h | 44 | 21.1 |
| 30 km/h | 63 | 30.2 |

## 轮速计算

### 轮胎参数 (16x2.50/64-305)

- 周长: 实测 1.28 m
- 磁钢: 1 个

### 计算方法

用**脉冲间隔**测速, 不是计数窗口:
```
1. 霍尔每过一个磁钢触发一次中断 (INPUT_PULLUP, 下降沿)
2. 相邻两次脉冲的间隔 = 转一圈的时间 (1 磁钢)
3. RPM = 60 / (间隔秒数 * 磁钢数)
4. km/h = RPM * 周长(m) * 60 / 1000
5. 协议值 = round(kmh * 25 / 12)
```

> 为什么不用计数窗口: 1 个磁钢在 17 km/h 下 250 ms 窗口只期望 0.9 个脉冲,
> 读数会在 0 和 ~24 km/h 之间乱跳。间隔测速在 17 km/h 时分辨率约 0.4%。
>
> 停转判定: 2 s 内没有新脉冲就认为停转, 车速归 0 (仪表显示驻车)。

## 完整通信流程

### 开机后轮询(每200ms一次)
```
1. 中控→BMS: 查询电量 (68 31 CE 68 02 02 60 42 75 16)
   BMS→中控: 返回电量 (68 31 CE 68 82 0F ...)

2. 中控→FOC: 查询状态 (68 20 DF 68 02 02 05 08 3B 46 16)
   FOC→中控: 返回状态 (68 20 DF 68 82 0E ...)

3. 中控→仪表: 显示信息 (68 10 EF 68 04 06 ...)
   仪表→中控: 确认 (68 10 EF 68 84 01 ...)
```

### 解锁流程
```
1. 中控→FOC: 0x01 03 (解锁命令)
2. FOC→中控: 0x81 + 16字节数据 (确认解锁)
3. 中控→FOC: 0x02 05 08 (状态查询,现在应该返回unlocked=1)
4. FOC→中控: 返回状态(带挡位信息)
5. 用户可以切换挡位
```
